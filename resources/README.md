# Resources

Everything the DCR tracker backend reads at runtime. The e-mail inbox lists every `.eml`/`.msg` file under this folder
(except `data/`, `output/` and `master_data/`), oldest first.

| Path | What it is |
|---|---|
| `template_SOP.xlsx` | The DCR tracker workbook (SOP 5-A1 "DCR Tracker and CAPA Overview"). Sheet **Main Sheet** is imported on first start; **Formulas** holds the drop-down lists; **Instructions and definitions** defines each field. |
| `SOP 5 - Attachment 2 - CAPA Report V4 1.docx` | CAPA report template (SOP 5, attachment 2). Not used by the code yet. |
| `sample_emails/*.eml` | 20 **synthetic** test e-mails modelled on real DCR threads (generated by `scripts/make_sample_emails.py`). |
| `20250342/`, `20251234/`, `20252275/`, `20252675/`, `20261234/` | **Real** Outlook e-mails (.msg), one folder per AMEX project. |
| `SHOWCASE/` | **Real** e-mail threads for the demo (projects 20241189, 20251792, 20260684). `20251792/…Miglustat (10).msg` is corrupt and is skipped. |
| `TEST NOW NEW ENTRIES/` | **Real** e-mails for incidents that are not yet in the tracker. |
| `SOP 5 - Attachment 1 - DCR Tracker and CAPA overview - V2 (October 2024).xlsx` | The original tracker file from the e-mail folder. Same 300 cases as `template_SOP.xlsx`; not used by the app. |
| `master_data/parties.json` | E-mail domain → partner lookup (currently the test e-mail domains). Project → customer/supplier lookups are learned from the tracker itself. |
| `output/DCR_Tracker.xlsx` | Working copy of the tracker that the app reads and writes (git-ignored). |
| `data/dcr_state.json` | Drafts, e-mails linked to each DCR, and ignored e-mails (git-ignored). `POST /api/admin/reset` clears both. |
